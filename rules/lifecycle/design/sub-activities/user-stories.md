# Design sub-activity — User Stories

> Trigger: **Produto** stream — new feature, journey, UX, or experiment. Optional,
> inside Design (the business Inception often arrives from an external agent, D33). Depth by mode.

## Purpose
Turn requirements into **user-centered stories with testable acceptance criteria**
and personas, so the team shares one understanding and Validate has clear targets.

## Inputs
`inception-input` (imported business Inception, when present), `requirements`,
affected personas/stakeholders.

## Steps
1. Identify the **personas** that the change serves.
2. Write each **story** as a user-centered narrative (who · wants · so that).
3. Define **acceptance criteria** per story — verifiable, the basis for Validate.
4. Do not refabricate the external business Inception (D33) — ingest and validate
   completeness; ask the origin if something is missing (never invent).
5. Link stories to the units/spec so each has a traceable acceptance path.

## Output
Stories + acceptance criteria + personas in the `spec` (and `requirements`);
acceptance criteria feed the Validate checklist.

## Depth by mode
FAST = one-line intent · Standard = stories + acceptance criteria ·
SAFE = + personas, edge journeys, and formal acceptance sign-off.
